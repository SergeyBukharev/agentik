# agentik.

![Agentik](public/illustrations/ideas.svg)

Меньше рутины. Больше жизни.

Agentik на React, TypeScript и Vite. Лендинг открыт всем. Каталог, чаты и история доступны после входа по коду. Vite запускает локальную проверку кода вместе с приложением.

## Запуск на Windows

Нужен Node.js 22.12+ (проект проверен на Node 24).

```powershell
cd D:\Agentik
npm ci
npm run dev
```

Откройте [Agentik](http://127.0.0.1:5173/agentik/). Укажите свободный порт командой `npm run dev -- --port 5174`, если 5173 уже занят. Также можно запустить `scripts/start.cmd`.

```powershell
npm run check       # тесты, TypeScript и production-сборка
npm run build
npm run preview     # проверка production-сборки, API входа и service worker
npx playwright install chromium webkit
npm run test:browser
```

## Вход по коду

Первый вход требует связи с API. Укажите путь к своему `codes-for-pro.txt` в серверной переменной `AGENTIK_CODES_FILE`. Настройте `AGENTIK_ACCESS_SECRET`, случайный секрет длиной от 32 символов. На новой установке скопируйте `.env.example` в игнорируемый файл `.env` и сгенерируйте значение, например командой `node -p "require('node:crypto').randomBytes(32).toString('hex')"`.

Файл принимает по одной записи на строку в формате `[КОД][метка]` или просто код. Каждый код содержит 6 латинских букв или цифр. Регистр игнорируется. Строку с меткой сервер читает только до конца первой группы. Поместите список в закрытую папку сервера за пределами `public`. После изменения файла перезапустите API. Секрет подписи должен сохраняться между перезапусками. Укажите `AGENTIK_ACCOUNT_EMAIL` и `AGENTIK_ACCOUNT_CODE`, чтобы связать конкретный код с email. Дополнительные адреса того же аккаунта перечислите через запятую в серверной переменной `AGENTIK_ACCOUNT_EMAIL_ALIASES`.

Отдельные клиентские аккаунты задаются массивом пар в серверной переменной `AGENTIK_CLIENT_ACCOUNTS`. Каждая пара имеет собственные идентификатор и сессию. Формат и проверка закрытого превью описаны в [инструкции развёртывания](docs/deployment.md).

Форма проверяет код после шестого символа и открывает историю чатов. При входе по ссылке на разговор или приглашение сохраняется адрес этого экрана.

## Пользовательское соглашение

Откройте `#/agreement` по ссылке на лендинге, в форме входа или в профиле. Внизу можно расписаться стилусом, пальцем или мышью либо ввести имя. Версия условий, время и подпись сохраняются в браузере отдельно для гостя и каждого аккаунта. Действие «Удалить отметку» очищает локальную запись.

## Что работает

- 32 практических помощника, 6 вымышленных персонажей, поиск и категории.
- Примеры первого запроса, демочат, история, избранное, свой помощник.
- Мобильный каталог без большого промоблока; нижняя навигация, короткие формы в шторках, desktop sidebar.
- Светлая и тёмная темы; доступные Radix Dialog, управление с клавиатуры, reduced motion.
- Отдельные локальные профили. История и избранное разделены по ID пользователя.
- Комнаты, участники, приглашения и обмен сообщениями между профилями/вкладками одного браузера.
- Анимированные SVG в `public/illustrations`; исходный компонент `src/components/Scene.tsx`.

## Сессии, кеш и скорость

Подписанная сессия действует **90 дней после входа**. Локальная история и кеш профиля обновляют отдельный 90-дневный срок при использовании. Разные коды открывают отдельные списки профилей. Активный аккаунт и профиль выбираются для каждой вкладки. Профили из сборки до введения входа читаются в прежней версии на её адресе.

Сохранённая сессия читается перед рендером. При доступной сети приложение подтверждает её в API в фоне. Каталог, сохранённые разговоры, демочат и локальные комнаты работают офлайн после первого успешного входа и полной установки service worker. При блокировке или очистке хранилища браузера потребуется войти ещё раз.

Профиль и комнаты загружаются отдельными модулями заранее в idle и по намерению пользователя. Форма входа предзагружается при наведении и фокусе. Скелетоны показываются во время загрузки, шрифты лежат локально и используют `font-display: swap`. WebGL загружается отдельно и учитывает системное уменьшение движения.

Service worker кеширует оболочку, иллюстрации и ресурсы одного поколения. Новая версия устанавливается целиком и активируется после закрытия старых вкладок. API и запросы с Authorization идут по сети.

## Как проверить локальный мультиплеер

1. Откройте «Чаты → Общие комнаты» и создайте комнату.
2. Скопируйте приглашение и откройте его в другой вкладке **того же origin и браузерного профиля**.
3. Во второй вкладке выберите «Профиль → Другой профиль», создайте участника и примите приглашение.
4. Отправьте сообщение. Оба участника увидят обновление через событие storage.

Ссылка действует 24 часа. Срок комнаты - 90 дней после изменения. Прототип хранит до 500 сообщений на комнату. Локальные проверки участников показывают поведение интерфейса, но не являются защитой от человека с доступом к DevTools. Для разных устройств и настоящего разграничения доступа нужен сервер. Одновременные записи в localStorage не транзакционны: прототип не предназначен для нагрузочного тестирования.

`src/local-rooms.ts` отделяет операции комнаты от UI. Будущий транспорт должен поддержать create/join/list/post/watch, ID сообщений, проверку участников, повторную доставку без дублей и серверный порядок событий. Опциональные `src/remote.ts`, `src/components/RemoteRooms.tsx`, `server/` и `supabase/` сохранены как заготовка; по умолчанию приложение их не требует. Серверный экран комнат сейчас не подключён к основным маршрутам.

## Опциональный настоящий AI

1. Укажите `AI_API_KEY` и `AI_MODEL` в серверном `.env`. При необходимости укажите `AI_API_BASE`.
2. Запустите локальный `npm run dev` или отдельный `npm run server` на узле API.
3. Войдите по коду. В профиле выберите «AI через сервер». AI использует сессию текущего аккаунта.

Для GitHub Pages требуется отдельный HTTPS API для входа и опциональных AI-запросов. Укажите публичный адрес через `VITE_API_URL`. Храните секреты кода и провайдера на сервере.

Опциональная схема Supabase: `supabase/migrations/001_rooms.sql`. Она рассчитана на свежий проект и требует настройки Auth/Realtime. SQL-проверки `supabase/tests/rooms.sql` выполняются psql на одноразовой тестовой базе. Облачная интеграция и SQL в настоящем Supabase в этой работе не проверялись: нет настроенной среды.

## Чаты и PRO

Пробный баланс аккаунта — 2 демотокена. Каждая принятая отправка в личном или групповом чате стоит 1 демотокен. Второе сообщение отправляется и открывает экран PRO. Повтор ответа токен не расходует. При активном PRO отправка включена. `AGENTIK_PRO_CODES` задаёт коды аккаунтов с доступом PRO на сервере. `VITE_PRO_CHECKOUT_URL` добавляет переход к уже настроенной оплате.

В сохранённом чате выберите «Поделиться» и передайте приглашение. В локальном режиме получатель открывает его под другим профилем в том же браузере. Действие «Сделать приватным» оставляет историю у владельца и отзывает приглашения и членство.

Добавляйте изображения через кнопку в поле сообщения. Удерживайте K вне текстовых полей, Alt+K в поле или кнопку микрофона на телефоне. Распознанный текст можно отредактировать перед отправкой. Доступность диктовки зависит от браузера, сети и разрешения на микрофон.
