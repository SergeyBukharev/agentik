# agentik.

![Agentik](public/illustrations/ideas.svg)

Меньше рутины. Больше жизни.

Рабочий frontend-прототип на React + TypeScript + Vite. Основные сценарии не требуют backend, API-ключей и регистрации. Демонстрационные ответы явно обозначены.

## Запуск на Windows

Нужен Node.js 22.12+ (проект проверен на Node 24).

```powershell
cd D:\Agentik
npm ci
npm run dev
```

Открыть напечатанный адрес, обычно http://127.0.0.1:5173/agentik/ . Также можно запустить `scripts/start.cmd`.

```powershell
npm run check       # тесты, TypeScript и production-сборка
npm run build
npm run preview     # проверка production-сборки и service worker
```

## Что работает

- 30 практических помощников, 6 вымышленных персонажей, поиск и категории.
- Примеры первого запроса, демочат, история, избранное, свой помощник.
- Мобильный каталог без большого промоблока; нижняя навигация, короткие формы в шторках, desktop sidebar.
- Светлая и тёмная темы; доступные Radix Dialog, управление с клавиатуры, reduced motion.
- Отдельные локальные профили. История и избранное разделены по ID пользователя.
- Комнаты, участники, приглашения и обмен сообщениями между профилями/вкладками одного браузера.
- Анимированные SVG в `public/illustrations`; исходный компонент `src/components/Scene.tsx`.

## Сессии, кеш и скорость

Локальная сессия действует **90 дней с последнего открытия профиля**. Сохранение истории продлевает её TTL до 90 дней; кеш каждого профиля использует свой ключ. Состояние читается синхронно до первого рендера, без сетевого ожидания. Активный профиль хранится отдельно в каждой вкладке; новый профиль в другой вкладке не переключает текущего участника комнаты.

Профиль и комнаты разбиты на отдельные JS-модули, предзагружаются в idle и по намерению пользователя. Скелетоны показываются при реальном ожидании модуля. Только нужные кириллические и латинские шрифты хранятся локально с `font-display: swap`.

Production service worker кеширует оболочку и хешированные статические ресурсы. HTML берётся из кеша той же версии, что и её JS/CSS. Новая версия устанавливается целиком и активируется после закрытия старых вкладок; её ресурсы не смешиваются с предыдущими. API-запросы и запросы с Authorization не кешируются. В dev service worker не регистрируется. Это ускоряет повторные открытия; абсолютную «мгновенную» загрузку на любой сети гарантировать нельзя.

Браузер может очистить данные раньше из-за действий пользователя, приватного режима или нехватки места. При отказе сохранения интерфейс показывает предупреждение. Локальный профиль не защищён паролем и не заменяет серверную авторизацию или резервную копию. Реальные access-токены не растягиваются на 90 дней; у подключённого провайдера авторизации свой срок и refresh.

## Как проверить локальный мультиплеер

1. Откройте «Чаты → Общие комнаты» и создайте комнату.
2. Скопируйте приглашение и откройте его в другой вкладке **того же origin и браузерного профиля**.
3. Во второй вкладке выберите «Профиль → Другой профиль», создайте участника и примите приглашение.
4. Отправьте сообщение. Оба участника увидят обновление через событие storage.

Ссылка действует 24 часа. Срок комнаты - 90 дней после изменения. Прототип хранит до 500 сообщений на комнату. Локальные проверки участников показывают поведение интерфейса, но не являются защитой от человека с доступом к DevTools. Для разных устройств и настоящего разграничения доступа нужен сервер. Одновременные записи в localStorage не транзакционны: прототип не предназначен для нагрузочного тестирования.

`src/local-rooms.ts` отделяет операции комнаты от UI. Будущий транспорт должен поддержать create/join/list/post/watch, ID сообщений, проверку участников, повторную доставку без дублей и серверный порядок событий. Опциональные `src/remote.ts`, `src/components/RemoteRooms.tsx`, `server/` и `supabase/` сохранены как заготовка; по умолчанию приложение их не требует. Серверный экран комнат сейчас не подключён к основным маршрутам.

## Опциональный настоящий AI

1. Скопируйте `.env.example` в `.env`.
2. Укажите серверные `AI_API_KEY`, `AI_MODEL`, `LOCAL_API_TOKEN` и при необходимости `AI_API_BASE`.
3. Запустите `npm run server` в отдельном терминале; frontend `npm run dev` проксирует `/api` на 127.0.0.1:3001.
4. В профиле откройте настройки AI, переключите режим и введите **LOCAL_API_TOKEN**, не ключ провайдера.

Этот токен хранится только в памяти до перезагрузки. Сервер слушает loopback, проверяет origin, авторизацию, размер сообщений, rate limit и timeout. Лимит rate limit находится в памяти одного процесса, не распределён. Для production нужен HTTPS, бюджетные квоты и внешний механизм ограничений.

GitHub Pages размещает только frontend. Для AI на Pages нужен отдельно развёрнутый API и `VITE_API_URL`. Переменные `VITE_*` публичны: **никогда не помещайте API-ключ или service_role в VITE_***. При настроенном Supabase сервер проверяет JWT через Auth API; LOCAL_API_TOKEN тогда не используется.

Опциональная схема Supabase: `supabase/migrations/001_rooms.sql`. Она рассчитана на свежий проект и требует настройки Auth/Realtime. SQL-проверки `supabase/tests/rooms.sql` выполняются psql на одноразовой тестовой базе. Облачная интеграция и SQL в настоящем Supabase в этой работе не проверялись: нет настроенной среды.
