# Agentik — описание проекта

Источник: https://chatgpt.com/share/6b07736d-4e6c-83ed-8a9f-3deac90b33d1

Рабочая папка: D:\Agentik. Документ составлен по доступной публичной копии чата. Это требования к будущей реализации, а не отчет о готовности. Архивы, упомянутые в чате, не получены. Полные исходные запросы и загруженные изображения в публичной копии не отображаются.

## Назначение

Agentik — русскоязычный сервис AI-помощников для повседневных задач. Слоган: «Меньше рутины. Больше жизни». Пользователь находит помощника, выбирает пример запроса и начинает разговор; позже возвращается к истории. Практические помощники и развлекательные персонажи представлены отдельно.

## Требования из переписки

- Адаптивный лендинг, логотип и собственный визуальный стиль.
- 30 практических помощников: работа, быт, творчество, обучение; примеры запросов.
- 6 персонажей для общения и ролевых сценариев.
- Поиск, категории, история разговоров, избранное.
- Создание собственного помощника.
- Групповые чаты и приглашения по ссылке; в переписке выбран Supabase.
- React + Vite, BEM, Inter и Manrope. Radix UI как основа доступных диалоговых окон.
- Подготовка для GitHub Pages по адресу https://sergeybukharev.github.io/agentik/: base /agentik/, hash-маршрутизация, workflow GitHub Actions.
- README, инструкции запуска и публикации, описание исследования и референсов, портрет аудитории, продуктовые гипотезы, журнал работы с AI.
- Юнит-экономика в XLSX: три сценария, затраты, стоимость функций и окупаемость.
- Маркетинговая стратегия в PDF: аудитория, позиционирование, боли, каналы и проверяемые гипотезы.

## Предлагаемые решения исполнителя

Эти решения выбраны исполнителем и пока не утверждены пользователем.

1. Создать новый проект на TypeScript, React и Vite. Хранить исходники, серверную часть, SQL, документы и скрипты в одной папке. Существующий проект отсутствует.
2. Главные экраны: лендинг; каталог помощников; каталог персонажей; чат; история; избранное. Создание помощника, профиль и приглашение — доступные диалоговые окна.
3. Локальный режим работает сразу: поиск, фильтры, избранное, создание помощников и история сохраняются в localStorage. Демонстрационные ответы явно обозначены; они не выдаются за результат настоящей модели.
4. Настоящий AI работает через отдельный серверный API с ключом провайдера в переменных окружения. Ключ не попадает в сборку браузера. GitHub Pages размещает только frontend. Базовая интеграция — OpenAI-совместимый API с настраиваемыми моделью и endpoint; платные запросы не выполняются без настройки пользователем.
5. Многопользовательский режим реализуется через Supabase Auth, таблицы участников и сообщений, Realtime и RLS. Приглашение требует проверки на сервере; знание идентификатора комнаты не дает доступа. Без настроенного Supabase интерфейс объясняет, что функция требует подключения. Локальная имитация не считается рабочим групповым чатом.
6. Документы содержат проверяемые ссылки, обозначенные предположения и формулы. Числа $12/месяц, $0,51 на активного пользователя, $45 960 разработки и 7 809 MAU из прежнего чата — неподтвержденные исходные гипотезы; их нужно пересчитать. Нельзя представлять их как исследованные факты.
7. Оригинальный интерфейс создается по описанию. Восстановление прежнего дизайна пиксель в пиксель невозможно без исходников и изображений. Платные исследования не подключаются. Референсы не называются просмотренными, если доступ к ним фактически не получен.

## Проверка результата

- Установка зависимостей, проверка TypeScript, production build.
- Содержательные тесты поиска и фильтрации, сохранения истории, обработки API-ошибок, проверки доступа к комнатам.
- Браузерная проверка основного пути на desktop и в мобильной эмуляции: поиск → помощник → запрос → история; создание помощника и избранное.
- Проверка клавиатурного управления, фокуса диалогов, пустых состояний и ошибок.
- Проверка формул XLSX и визуального отображения PDF.
- Интеграционные проверки Supabase и AI отдельно отмечаются как невыполненные, пока нет настроенной среды. Эмуляция не называется тестированием на физическом устройстве.

## Границы текущей работы

Создать локальный сервис и перечисленные файлы, проверить доступные сценарии, подготовить публикацию. Создание внешних аккаунтов, публичная публикация, push в GitHub, покупка сервисов и ввод ключей не входят в эту локальную реализацию. Секреты не извлекаются из скриншотов прежнего чата. Репозиторий портфолио не изменяется.
