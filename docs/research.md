# Основания продуктовых и мобильных решений

## Что известно

Пользователь просил основные frontend-сценарии, будущую мультиплеерную логику, сессию/кеш каждого пользователя не меньше 90 дней, prefetch, skeleton loading, выразительные SVG-анимации и минимальный mobile-first интерфейс. Собственной аудитории и аналитики Agentik в исходных данных нет. Не проводились интервью или количественные эксперименты.

Внешний контекст: [OpenAI, How people are using ChatGPT](https://openai.com/index/how-people-are-using-chatgpt/) выделяет практические советы, поиск информации и работу с текстом как крупные категории использования. Это поддерживает проверку практических помощников, но не доказывает их востребованность в Agentik.

## Сценарий пользователя

Найти помощника под задачу → выбрать пример или написать запрос → увидеть ответ → сохранить помощника → продолжить разговор из истории. Для совместного сценария: создать комнату → передать приглашение → второй профиль принимает → участники обмениваются сообщениями.

Из этого сценария следуют гипотезы: поиск должен быть доступен сразу; основные разделы должны переключаться без открытия меню; новый разговор должен быть отделён от истории; демонстрация AI и локальных комнат должна быть ясно названа.

## План проверки на пользователях

Провести 8-10 интервью с людьми, недавно решавшими текстовую, бытовую или учебную задачу; затем 5-8 мобильных наблюдаемых сессий. Фиксировать выбор помощника, ошибки, первый запрос, успешный возврат к истории, создание комнаты. Не объявлять результаты до фактических исследований. Протоперсоны в PDF - гипотезы для рекрутинга.

События будущей аналитики: assistant_open, starter_selected, message_sent, reply_received, favorite_added, history_opened, room_created, invite_accepted. Тексты сообщений не должны попадать в аналитику. Сейчас внешние системы аналитики не подключены.

## Технические основания

- [W3C: Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum) и [Enhanced](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced). Для мобильных основных действий целевой размер около 44 CSS px и больше; это проверяется отдельно от наличия aria-label.
- [Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog): семантика, Escape, фокус и модальный контекст.
- [Vite Static Deploy](https://vite.dev/guide/static-deploy.html): base подпути и GitHub Actions.

Браузерная мобильная эмуляция не заменяет физические устройства, экранный диктор и проверку системной клавиатуры.
