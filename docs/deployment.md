# Публикация Agentik

Исходники, документы и архив Telegram доступны в репозитории `SergeyBukharev/agentik`. Публичная версия работает на GitHub Pages. Рабочие аккаунты остаются в окружении серверного API. [Репозиторий](https://github.com/SergeyBukharev/agentik) · [Публичный вход](https://sergeybukharev.github.io/agentik/#/login)

## Закрытое превью

1. Собрать фронтенд через `npm ci` и `npm run build`. Разместить `dist` под `/agentik/` и Node API под `/api/` на одном HTTPS-адресе. При разных доменах задать `VITE_API_URL` и `ALLOWED_ORIGIN`.
2. Ограничить доступ ко всему превью на шлюзе по подтверждённой почте клиента, включая HTML, JS и ассеты. Шлюз остаётся поверх входа Agentik, который разделяет аккаунты и историю. За шлюзом установить лимит запросов по адресу клиента.
3. Настроить независимые пары в серверной переменной `AGENTIK_CLIENT_ACCOUNTS`. Пример для тестовой среды `[{"email":"viewer@example.test","code":"7M4ZQ8"}]`. Использовать уникальный код для каждого аккаунта. Избегать дублирования клиентских кодов в `AGENTIK_CODES_FILE` и у владельца.
4. Проверить, что анонимный запрос HTML, JS и API отклоняется и что клиентский вход создаёт свой аккаунт. Для отзыва убрать email со шлюза, удалить пару из серверной переменной и из списка кодов, если она туда попадала, затем перезапустить API. Доступ к API прекратится. Скачанные браузером файлы и локальная офлайн-история могут сохраниться на устройстве.

При первом показе используйте деморежим. Для живого AI нужны серверные квоты и перенос инструкций встроенных помощников с фронтенда в серверный каталог по `assistantId`. Рабочие коды и ключи хранятся в серверном окружении.

## Демо на GitHub Pages

Версия в `SergeyBukharev/SergeyBukharev.github.io` раздаётся из папки `agentik/` ветки `main`. Для обновления соберите `dist` с `VITE_DEMO_ACCESS=true` и пустым `VITE_API_URL`, затем обновите файлы этой папки. Workflow Pages в репозитории исходников запускается вручную. [Как работает GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

На экране входа нажмите «Демо Free» или «Демо PRO». Можно также ввести публичные тестовые данные.

| Профиль | Email | Код |
| --- | --- | --- |
| Free | `free@demo.agentik.test` | `FREE26` |
| PRO | `pro@demo.agentik.test` | `PRO026` |

У каждого демопрофиля своя история в браузере. Для серверного входа задайте `VITE_API_URL`. Закрытое Sites-превью при необходимости подключается через `VITE_ACCESS_PREVIEW_URL` в сборке без режима `VITE_DEMO_ACCESS`.

`vite.config.ts` использует base `/agentik/`. Прямые ссылки на чаты используют `#/…`. Для неверных путей сборка создаёт `dist/404.html`. При смене подпути обновите `base` и пересоберите приложение. Service worker получает область из той же конфигурации.

## HTTPS API

GitHub Pages размещает файлы интерфейса. Запустите `npm run server` на отдельном узле Node.js за HTTPS и настройте:

- `AGENTIK_CODES_FILE` с приватным путём к списку кодов на узле.
- `AGENTIK_ACCESS_SECRET` с постоянным случайным секретом.
- `AGENTIK_ACCOUNT_EMAIL` и `AGENTIK_ACCOUNT_CODE` для парного входа.
- `AGENTIK_ACCOUNT_EMAIL_ALIASES` для дополнительных адресов того же аккаунта через запятую. `AGENTIK_CLIENT_ACCOUNTS` создаёт отдельные аккаунты для клиентов.
- `AGENTIK_PRO_CODES` для выдачи PRO через серверную конфигурацию.
- `ALLOWED_ORIGIN` с адресом Pages без подпути, например `https://sergeybukharev.github.io`.
- `AI_API_KEY`, `AI_MODEL` и при необходимости `AI_API_BASE` для режима AI.

При сборке передайте HTTPS-адрес API в `VITE_API_URL`, например `https://api.example.com`. В переменные `VITE_*` передаются только публичные значения. Код доступа проверяется на сервере. Сброс подписи аннулирует выданные сессии. Исключение записи из списка и перезапуск API прекращают её принятие онлайн.

Лимит попыток хранится в памяти процесса. На узле за прокси приложение видит адрес прокси, поэтому для публичного запуска настройте ограничение запросов по адресу клиента на прокси. Встроенный лимит покрывает одиночный локальный или небольшой сервер.

Service worker обновляется при следующем открытии; новая версия активируется после закрытия старых вкладок. Он не делает агрессивный skipWaiting, чтобы не смешивать версии. При диагностике старой сборки закрыть все вкладки приложения и открыть заново.

## Баннер и иллюстрации

После первого чата на главной открывается каталог. `VITE_SERVICE_ANNOUNCEMENTS` принимает JSON-массив объявлений с `id`, `kind`, `title`, `description` и необязательными `titleEn` и `descriptionEn`. Значение `important` в `kind` выводит сообщение перед `promotion`. Пустой список скрывает слайдер.

После изменения палитры или общего маскота обновите SVG командой `node --import tsx scripts/render-illustrations.ts` и CSS-токены командой `node scripts/color-tokens.mjs`.

## Telegram Mini App

Выполните `node scripts/package-telegram-mini-app.mjs`, чтобы собрать архив с Node-сервером, интерфейсом Mini App, отдельным виджетом и документацией. Mini App и API работают на одном HTTPS-домене. Связь с ботом, переменные окружения и проверка ссылки описаны в [инструкции Telegram](telegram-mini-app.md).
